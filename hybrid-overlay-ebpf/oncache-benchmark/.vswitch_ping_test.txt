## Summary / findings
1. Direct ICMP between logical vSwitch addresses 10.0.2.2 and 10.0.2.3 does not work; both sides report Destination Host Unreachable from their public primary addresses.
2. 10.0.2.x and 10.0.3.x are configured on loopback on each machine; forwarding to the peer uses onlink routes via the other host's public /32 on enp4s0/enp1s0, which does not deliver ICMP to the peer's loopback aliases.
3. GRE oncache path (10.99.0.x) is how 10.0.3.2/10.0.3.3 are reached remotely (route get shows gre-oncache).
4. netperf workloads use bench-net (10.0.1.x), not bench-ipvlan; no 10.0.3.2 container ping test was run.
5. enp8s0 on server1 has NO-CARRIER; not a fix for current ping failure without Hetzner private network attachment.
